# Castle Destroyers — Roadmap разработки (Claude Code + ревью заказчика)

> **Обновление (ТЗ 1.1)**: визуал — стилистика Bowmasters, плеебл многокликовый (3 хода). Затронуты этапы 1, 3, 6, 7. Этап 0 не меняется.

Спецификация — `docs/TZ.md`. Правила работы агента — `CLAUDE.md`. Решения — `docs/DECISIONS.md`.

## Как устроен процесс

```
 ┌──────────── Claude Code (автономно) ───────────┐     ┌──── Ты ────┐
 │ читает этап → план → код → самопроверка →       │ ──▶ │ ревью в    │
 │ отчёт docs/reports/STAGE_N.md → коммит → СТОП   │     │ Editor/на  │
 └─────────────────────────────────────────────────┘     │ телефоне   │
            ▲                                             └─────┬──────┘
            │   "APPROVED"  → следующий этап                    │
            └── "FEEDBACK: …" → доработка в том же этапе ◀──────┘
```

- **Один этап — одна ветка** `stage/NN-name`. После APPROVED ты мержишь ветку в `main` (или поручаешь это Claude Code).
- Внутри этапа агент решает сам: структура классов, имена, мелкие визуальные решения, дефолтные значения параметров. Всё, что расходится с ТЗ, записывается в `DECISIONS.md` с пометкой «нужно подтверждение».
- **Стоп-точки** — места, где агент обязан остановиться и спросить: изменение стека, добавление пакетов, отказ от требования ТЗ, превышение бюджета размера или FPS, которое не решается в рамках этапа.
- Числа, которые ты будешь крутить в ревью, — в `GameConfig` (инспектор). Фидбек по механике удобно давать так: «rocketInterval 0.06 → 0.04, синусоида шире».
- **Luna smoke-build** собирается на каждом этапе, начиная с 3-го. Несовместимость с Luna должна всплывать сразу, а не в конце.

### Шаблон запуска этапа (вставить в Claude Code)
```
Этап N из docs/ROADMAP.md. Прочитай CLAUDE.md, docs/TZ.md (разделы этапа), docs/DECISIONS.md
и отчёты предыдущих этапов. Составь план (TaskCreate), потом выполняй автономно.
Закончи отчётом docs/reports/STAGE_N.md по шаблону из CLAUDE.md, коммитом и остановкой.
```
### Шаблон фидбека
```
FEEDBACK этап N:
1. [механика] ракеты летят слишком медленно — ускорить ~30%
2. [графика] кайма кратера в земле слишком тёмная
3. [баг] при смене ориентации пропадает рука-подсказка
Остальное ок. Доработай, обнови отчёт (раздел "Итерация 2"), коммит, стоп.
```

## Этап 0 — Настройка и технический спайк (GO / NO-GO)
**Цель**: до написания игры доказать, что архитектура из ТЗ §5 работает в Luna на реальном Android.

Предусловия с твоей стороны:
- установить Unity **6000.0 LTS** с модулем WebGL;
- завести аккаунт Luna и установить Playworks Plugin;
- создать git-репозиторий;
- скопировать референсы в `docs/references/`.

Claude Code делает:
- проект URP (Universal Renderer, без 2D Renderer), структуру папок, `.gitignore` для Unity, asmdef `Game.Runtime` / `Game.Editor` / `Game.Tests`;
- **Spike-сцену** с переключаемыми тестами:
  1. маска 512×512 тайлами, запись кратеров по клику и `Texture2D.SetPixels32/Apply` по грязным тайлам, кастомный шейдер (mask cutout + кайма);
  2. 1000 «ракет» — квады в одном динамическом меше, движение по синусоиде (SoA на `float[]`);
  3. 2000 частиц дыма в отдельном меше;
  4. тач-ввод и ресайз под ориентацию;
  5. вызов CTA-заглушки через Luna API.
- скрипт-проверку размеров ассетов и замер итогового HTML;
- черновик `DECISIONS.md` с выбором варианта масок (`Texture2D` или RenderTexture-фоллбэк).

Ты проверяешь:
- Luna-превью spike-сцены на своём телефоне (по QR или ссылке из Luna);
- FPS в оверлее при 1000 ракетах и непрерывных кратерах;
- размер билда в отчёте.

**Критерии GO**:
- маска визуально обновляется в Luna-сборке;
- ≥ 30 FPS на слабом девайсе при 600 квадах-ракетах и 4 тайловых аплоадах на кадр;
- пустая сборка ≤ 2 MB.

Если что-то не проходит, агент описывает альтернативу (RenderTexture-штамп, меньшее разрешение масок) и ждёт решения.

## Этап 1 — Каркас игры и greybox
- `GameBootstrap`, `GameLoop` (порядок Tick), `GameConfig` SO со всеми параметрами ТЗ (часть пока не используется), свой `Rng`, пулы.
- Стейт-машина сессии из ТЗ §3.1 с заглушками, переходы по таймерам.
- Greybox-уровень: прямоугольники-замки, контур горы, бустеры-прямоугольники, вода.
- Базовая камера: переезды между точками интереса по состояниям (SmoothDamp).
- Каркас многокликовой структуры: `maxPlayerTurns`, массив `TurnHint[]` в конфиге (пока без визуала), счётчик ходов в оверлее.
- `ThemePalette` (SO) с пресетами `Night` / `Sunset`. Greybox сразу красится в цвета палитры, чтобы с первого этапа видеть контраст объектов на фоне.
- Debug-оверлей (FPS, состояние FSM, счётчики) и чит-панель: «следующее состояние», «x0.25 скорость», «спавн 1000 ракет».
- EditMode-тесты на FSM и пулы.

**Ты проверяешь**: в Play Mode в Game view 720×1280 цикл «ход игрока → ход ИИ → … → victory → endcard» проходит на заглушках, камера переезжает плавно.

## Этап 2 — Разрушаемый ландшафт
- `DestructibleMask` для ландшафта по маске-картинке уровня 1 (SVG-источник → PNG скриптом). Гора с расщелиной, холмы, размеры по ТЗ §3.8.
- `CraterStamper`: круг с тёмной каймой для земли.
- `ConnectivitySolver` + `ChunkExtractor`: отвалившиеся острова земли падают в воду без коллизий, мелочь исчезает с пылью.
- Шейдер ландшафта: земля (тёмная почва) + травяная кромка по верху (определяется по маске) + кайма кратеров.
- Вода: полоса с волной по кромке и всплесками (пул).
- Debug: клик мышью или тап = взрыв заданного радиуса.

**Ты проверяешь** (Editor): форму уровня против кадра 3, вид кратеров в земле, что прострелянная насквозь гора и отколотые куски падают корректно. Плюс Luna smoke-build (не обязательно).

## Этап 3 — Пушки, прицеливание, ракеты
- Ввод прицела в стиле Bowmasters (ТЗ §3.2): жест «оттянуть», угол + сила → `launchSpeed`, мёртвая зона. Пунктир из белых точек (первые ~30% траектории), плашка POWER / ANGLE (greybox-версия).
- `CannonSystem`: маунты, синхронный поворот, залп (по 10 ракет с каждой пушки, чередование стволов, отдача, вспышка).
- `RocketSystem` (SoA): баллистика + синусоида, ориентация по касательной, коллизия по маскам (сегментный тест, без туннелирования на высокой скорости), бюджет `maxActiveRockets`.
- `ExplosionSystem`: батч-визуал взрывов, слияние близких, штамп кратеров, screen shake с насыщением.
- Дым: батч-шлейфы с LOD.
- Stress-сцена «1000 ракет в гору» с замером.
- **Luna smoke-build** + замер FPS на телефоне.

**Ты проверяешь**: удобство прицела «сила + угол» на телефоне (попадается ли x20 с 1–2 попыток), ощущение стрельбы — темп, змейка, скорость, дым, взрывы. Поток прогрызает тоннель в горе. FPS в Luna-сборке. Здесь основной фидбек по механике.

## Этап 4 — Бустеры
- `BoosterSystem`: AABB-триггеры, умножение по правилам ТЗ §3.5 (веер, разнос по времени, «уже умножено этим бустером»), бюджет и `damageWeight`.
- Визуал-greybox+: цветные «стеклянные» прямоугольники с числом, «пых» и сквош при срабатывании, поп-ап «+N».
- Сценарии проверки (кнопки в debug-панели): навес через x20; тоннель через левую половину горы → x10 → насквозь; низ → x50.

**Ты проверяешь**: читаемость эффекта «ракет стало в N раз больше», выход копий «несколькими змейками» (кадр 9), стабильность FPS при x50.

## Этап 5 — Замки: разрушение, платформа, отрыв пушек
- `Castle`: маска замка из альфы спрайта; погрызанный кратер; кайма; трещины (процедурные ломаные, пишутся в B-канал).
- Связность замка (опора — платформа), падающие куски вместе с пушками, мелочь → пыль.
- Платформа и гусеницы: посадка на ландшафт, наклон, оседание при разрушении земли, падение в воду.
- Sway от урона (пружина, насыщение).
- Отрыв пушек по трём условиям (ТЗ §3.3), падение и всплеск, счётчик живых пушек.
- Два замка разной формы — пока greybox-силуэты по кадрам 1 и 4.
- **Luna smoke-build.**

**Ты проверяешь**: что разрушение замка «как в ролике» (кадры 5–7, 11–12), что пушки отваливаются убедительно, что наклон и покачивание не дёрганые.

## Этап 6 — ИИ, ходы, победа, режиссура камеры
- ИИ: пресеты углов (через x20, по прямой, «тоннель»), шум по сложности, задержка-«раздумье» с видимым поворотом пушек.
- **Многокликовая структура (ТЗ §3.1.1)**: 3 хода игрока с подсказками из `TurnHint[]` — ход 1 на x20, ход 2 подсветка x50 и «прямой» выстрел в гору, ход 3 без руки. Плашки «YOUR TURN!» / «ENEMY TURN».
- Director: гарантированная победа игрока к `maxPlayerTurns` (вкл./выкл.), «добивающий» последний залп, лимит по времени, idle-логика (рука через 3 с, автовыстрел по подсказке хода через 10 с).
- HUD (greybox+): сегментированные полосы здоровья сторон (сегмент = пушка), иконки замков, реакция на отрыв пушки.
- (Опционально, если `bonusPickEnabled`) — выбор бонуса между ходами.
- Полная хореография камеры из ТЗ §3.9, включая ландшафтную ориентацию.
- Victory: прыгающие пушки, фейерверк за замком, затем EndCard (greybox) и CTA-заглушка.
- Поражение игрока → EndCard «Try again».

**Ты проверяешь**: весь матч целиком 3–5 раз. Каждый из 3 кликов ощущается отдельным «вау», подсказки понятны без текста, HUD читается. Темп, драматургия, длительность ≤ 75 с, работа камеры.

## Этап 7 — Арт-пасс в стилистике Bowmasters, UI, звук
- Сначала **style sheet** (`docs/reports/img/style_sheet.png`): палитры `Night` / `Sunset` (HEX пипеткой со скриншотов `docs/references/style/`), образцы замка, земли с кромкой, бустера, ракеты, взрыва, HUD-пилюли — на одном листе рядом со скриншотами Bowmasters. **Стоп-точка: апрув style sheet до отрисовки всего остального.**
- SVG-источники всего арта (`Art/Source`) по правилам ТЗ §4.1 — плоско, без обводок, 2–3 тона на форму: два замка, крыши, платформа, гусеницы, трёхстволки (2 цвета), ракеты (2 цвета), бустеры ×3, земля (масса, волнистая или «капающая» кромка, «закопанные» декоры), ёлки, кусты, голые деревья, камни, фоновые слои ×5 (небо, луна или солнце, горы, лес или город с окнами, ближний план), вода, рука, иконки замков для HUD, иконка «скрещённые ракеты», кнопка, логотип «CASTLE DESTROYERS», EndCard.
- Скрипт растеризации SVG → PNG + упаковка атласов, оптимизация (pngquant / JPG для фонов).
- Параллакс 5 слоёв с учётом зума, дождь.
- Полировка VFX в плоском стиле: взрыв-«звезда» из 2–3 кругов, плоские осколки, дым-пуфы, искры-звёздочки фейерверка, пыль, всплески. Сквош и стретч на выстреле, бустере, отрыве пушки.
- UI в стиле Bowmasters: фиолетовые пилюли, полосы здоровья, плашка POWER / ANGLE, пунктир, рука-туториал, поп-апы, плашки хода, EndCard с пульсирующей PLAY NOW, безопасные зоны. Шрифт — OFL (Fredoka / Baloo 2), подмножество глифов.
- Звуки (≤ 150 KB суммарно), mute до первого тапа.
- Отчёт со скриншотами ключевых моментов рядом с референс-кадрами.

**Ты проверяешь**: стиль против скриншотов Bowmasters — «похоже на одну игру», без заимствованных персонажей и ассетов. Итерации по графике идут здесь: «фон на ступень темнее», «кромка земли толще». Если есть официальный арт — подменяешь SVG или PNG, пайплайн тот же.

**Ты проверяешь**: установку и прохождение на 2+ Android-устройствах (слабый и средний) по ссылкам превью сетей; переход в стор.

## Рекомендации по инструментам
- **Claude Code + Unity**: агент компилирует и гоняет тесты через `Unity.exe -batchmode -projectPath . -runTests …` и читает `Editor.log`. Для большей автономности можно подключить Unity MCP-сервер (например, open-source `unity-mcp`): агент сам читает консоль, запускает Play Mode и делает скриншоты Game view. Актуальность и совместимость с Unity 6000.0 проверить при установке.
- **Ревью графики**: агент кладёт скриншоты (Editor, Game view 720×1280) в `docs/reports/img/`, рядом с референсом.
- **Ревью механики**: ты в Play Mode + debug-панель (замедление, рестарт хода, форс-победа) + Luna-превью на телефоне.
