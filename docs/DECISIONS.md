# Журнал решений (ADR-lite)

Формат: `D-NNN · дата · статус (принято | нужно подтверждение | отменено)`. Контекст → решение → альтернативы.

### D-001 · 2026-10-30 · принято
**Экспорт через Luna (Unity Playworks), Unity 6000.0 LTS + URP 17.0.x.**
Контекст: лимит 5 MB single-HTML у AppLovin и Unity Ads. Обычный Unity Web build с трудом укладывается в 5 MB даже пустым.
Альтернативы: Unity Web build + свой упаковщик в HTML (большой риск по размеру); переписать на JS-движок (уходим из Unity).

### D-002 · 2026-10-30 · принято
**Без DOTS/ECS и без физического движка. Data-oriented C# (SoA), собственные коллизии по маскам.**
Контекст: в Luna нет DOTS/Burst/Jobs, 2D-физика исторически нестабильна. Нужно 600–1000 ракет на слабом Android.

### D-003 · 2026-10-30 · нужно подтверждение (по итогам этапа 0)
**Разрушаемость: CPU-маска + `Texture2D` по грязным тайлам.** Фоллбэк — штамповка в RenderTexture.
Решается спайком на этапе 0: работает ли быстрая запись в текстуру в Luna-сборке.

### D-004 · 2026-10-30 · нужно подтверждение
**Число пушек по умолчанию: синий 3, красный 12** (референс: 1 и 14).
Контекст: при одной пушке игрок проигрывает от первого же ответного залпа, а плеебл должен давать победу.

### D-005 · 2026-10-30 · нужно подтверждение
**Режиссура: игрок гарантированно выигрывает к 3-му ходу; сессия ≤ 60 с; поражение тоже ведёт на EndCard.**

### D-007 · 2026-10-30 · принято
**Арт — оригинальный SVG, рисует агент; EndCard и логотип свои.** Ассеты и персонажей чужих игр не копируем. *Стилевой ориентир заменён — см. D-014.*

### D-008 · 2026-10-30 · принято
**Playworks Plugin 7.2.0 подключён локальным UPM-пакетом и лежит вне репозитория.**
Контекст: дистрибутив весит 590 MB и должен лежать вне проекта (рекомендация документации Luna).
Решение: в `Packages/manifest.json` — `"com.unity.playworks.upp": "file:../../Unity Playworks Plugin/7.2.0/scripts"`. Путь относительный, поэтому на другой машине папка `Unity Playworks Plugin` должна лежать рядом с папкой проекта.
Альтернативы: копия `scripts` в `Packages/` (отрывает пакет от `engine`/`pipeline`/`tools`); весь дистрибутив в git (590 MB).

### D-009 · 2026-10-30 · принято
**Пакеты: добавлен URP 17.0.4, удалены неиспользуемые `com.unity.feature.2d`, `timeline`, `visualscripting`, `multiplayer.center`, `collab-proxy`.**
Контекст: в проекте не было URP, хотя стек его требует. `com.unity.feature.2d` с URP давал ошибки компиляции в `2d.pixel-perfect`, а `timeline` есть в списке неподдерживаемых пакетов Luna (`supported-packages.json`).
Альтернативы: чинить версии 2D-пакетов (не нужны: арт идёт через свои меши и uGUI).

### D-010 · 2026-10-30 · принято
**Цветовое пространство — Gamma.**
Контекст: минимальная платформа — WebGL 1, где Linear опирается на необязательные sRGB-расширения. Цвета в арте и шейдерах считаем в гамме.
Альтернатива: Linear (риск расхождения цветов между устройствами, выигрыша для плоской мультяшной графики нет).

### D-011 · 2026-10-30 · нужно подтверждение (по итогам Luna-сборки)
**Динамические меши обновляются через `Mesh.vertices` / `Mesh.colors32` с переиспользуемыми массивами; поля элементов пишутся на месте.**
Контекст: в Luna 7.2.0 нет перегрузок `SetVertices(Vector3[], …)`, `SetVertexBufferData`, `LoadRawTextureData`, `SetPixelData`. Для тайлов масок есть только `SetPixels32`. `Vector3[]` и `Color32[]` выделяются один раз в `Init`, в горячем цикле меняются только поля `x/y/r/g/a`, поэтому копий struct-ов нет.
Фактическую цену этих вызовов в JS покажет HUD спайка (строка `ms`).

### D-012 · 2026-10-30 · принято
**Сборка Luna запускается через `Tools/luna_build.py`.**
Контекст: `project:build` пишет задание `Assets/.export-assets` и ждёт экспорта, а `LunaCLI.Export` в batchmode выполняет это задание. Поодиночке оба зависают, и даже вместе Jake не замечает конец экспорта. Поэтому скрипт запускает их вместе, затем завершает Jake и отдельно выполняет `assets:bundle`, `code:bundle`, `package:bundle`. Нужен вход в Playworks Plugin, Unity должна быть закрыта.

### D-013 · 2026-10-30 · принято
**Итоговый HTML под сети собирается только в Luna Playground.**
Контекст: в плагине 7.2.0 локально есть только шаблоны `develop` и `playground`, сборка с `TARGET_PLATFORM=applovin` падает. Поэтому бюджеты размера проверяются после загрузки архива в Playground, локально виден только размер архива.

### D-014 · 2026-10-30 · принято (требование заказчика)
**Визуал — стилистика Bowmasters; механика — из ролика с замками.**
Контекст: в задании появилось новое требование — повторить механику референс-ролика, но сохранить стиль Bowmasters.
Решение: плоский вектор без обводок, монохромные локации, земля с цветной волнистой кромкой, HUD из фиолетовых пилюль с полосами здоровья, прицел «сила + угол» с плашкой POWER / ANGLE (TZ §3.2, §3.12, §4). Стиль повторяем, а не ассеты: без персонажей, логотипа, иконок и шрифта Bowmasters. Вместо портретов персонажей — иконки замков.
Альтернативы: оставить стиль ролика (противоречит требованию).

### D-015 · 2026-10-30 · принято (требование заказчика)
**Многокликовый плеебл: 3 хода игрока с нарастающими подсказками (x20 → x50 через гору → свободный ход).**
Контекст: нужна многокликовая версия, а не «один тап → автопроигрывание». TZ §3.1.1.
Альтернативы: 2 хода (короче, меньше вовлечения); бонус-выбор между ходами — заложен флагом `bonusPickEnabled`, по умолчанию выключен.

### D-016 · 2026-10-30 · нужно подтверждение
**Палитра по умолчанию — `Night` (тёмно-синяя, как кладбище Bowmasters); дождь из ролика выключен; лимит сессии увеличен до 75 с из-за 3 ходов.**
Альтернативы: `Sunset` (тёплая) — пресет готовится параллельно и переключается в конфиге.

### D-017 · 2026-10-30 · нужно подтверждение (по итогам плейтеста этапа 3)
**Прицел — «оттянуть» с силой и углом, как в Bowmasters.** Альтернатива в конфиге — «направление на палец» без силы: проще для случайного рекламного игрока, но меньше похоже на Bowmasters.

### D-018 · 2026-10-30 · принято
**FSM сессии: состояния `Aim / Fire / Flight / Resolve` + поле `ActiveSide`, вместо пар `PlayerAim` / `AIAim` и т. д.**
Контекст: ТЗ §3.1 описывает симметричный цикл для обеих сторон. Одна пара состояний на сторону удваивает таблицу переходов, камеры и HUD.
Решение: состояния `Boot, Intro, Aim, Fire, Flight, Resolve, Victory, Defeat, EndCard`, чья очередь — `SessionFlow.ActiveSide`. Бой до этапа 3 заменён заглушкой: потери пушек за залп берутся из `GameConfig` (`stubEnemyLossPerPlayerTurn`, `stubPlayerLossPerAiTurn`), Director добивает врага на последнем ходу игрока и не убивает последнюю пушку игрока. Все переходы по таймерам; `Skip()` — досрочный переход для читов и будущего автовыстрела.
Альтернативы: отдельные `PlayerAim` / `AIAim` (больше кода без выигрыша).

### D-019 · 2026-10-30 · принято
**Символ `GAME_DEBUG` включён в Standalone и WebGL, пока не начался этап 9.**
Контекст: правило CLAUDE.md — debug-код только за `#if GAME_DEBUG`. Чтобы FPS-оверлей и читы были и в Luna-превью на телефоне (этапы 3, 5), символ нужен в WebGL-сборке.
Решение: `Editor/DebugDefines.cs` ([InitializeOnLoad]) следит за символом в `ProjectSettings`. В коде без символа `GameBootstrap` удаляет `debugRoot`, а `DebugOverlay` и `DebugRocketStress` не компилируются. На этапе 9 снять символ у WebGL и убрать `DebugDefines`. Сцена хранит ссылку на `DebugOverlay`: в релизе это компонент без скрипта, его надо вычистить из сцены (долг этапа 9).
Альтернативы: ставить символ вручную в Player Settings (легко забыть, не воспроизводимо из batchmode).

### D-020 · 2026-10-30 · принято
**Greybox-уровень — один статичный меш с вершинными цветами и шейдером `Game/FlatColor`; контур ландшафта — ломаная в `GameConfig.terrainProfile`.**
Контекст: этапу 1 нужны замки, гора, бустеры и вода в цветах палитры, а маски и арт появятся на этапах 2, 5, 7.
Решение: `GreyboxLevel` собирает фон, землю с кромкой, воду, замки и бустеры в один меш в порядке отрисовки (один draw call), при смене темы меш пересобирается. Ломаная ландшафта и позиции бустеров и замков лежат в конфиге и переиспользуются этапами 2–4. Размеры силуэтов замков — именованные константы в `GreyboxLevel` (живут до арт-пасса).
Альтернативы: SpriteRenderer на каждый объект (лишние draw calls, нужны спрайты, которых ещё нет).

### D-021 · 2026-10-30 · принято
**Кадр камеры задаётся шириной в метрах и минимальной высотой, а не `orthographicSize`.**
Контекст: портрет (720×1280) и ландшафт должны показывать одни и те же точки интереса (ТЗ §2.2, §3.9).
Решение: `castleFrameWidth`, `centerFrameWidth`, `targetFrameWidth` и `minFrameHeight` в конфиге; `CameraFraming.OrthoSize` берёт большее из требуемого по ширине и по высоте. В ландшафте ограничивает `minFrameHeight`, в портрете — ширина. Центральный кадр самый широкий, кадр на цели чуть уже (ТЗ §3.9).
