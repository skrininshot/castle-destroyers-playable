# Castle Destroyers — Техническое задание на плеебл (Unity → playable ad)

Версия: 1.0 · Дата: 2026-10-30
Источник: текстовое описание заказчика + раскадровка `docs/references/*.jpg` + ролик `castle_destroyers_video.mp4`.

Термины: **плеебл** (playable ad) — интерактивная реклама в одном HTML-файле или ZIP-архиве. **Сторона**: синие (игрок) и красные (ИИ). **Залп** — одновременный выстрел всех живых пушек стороны. **Маска** — CPU-битмап «есть материал / нет материала» у разрушаемого объекта.

---

## 1. Цель продукта

Короткий (≈30–60 с) интерактивный рекламный ролик в стиле Worms. Игрок прицеливается, его замок даёт залп ракетами, ракеты размножаются в бустерах и сносят замок противника. В конце показывается экран с CTA «PLAY NOW», который ведёт в Google Play.

Ключевая эмоция — **«вау, сколько ракет»**: игрок выпускает несколько десятков ракет, а к цели прилетают сотни. Всё в кадре рушится, пробиваются тоннели насквозь.

### 2.2 Наши целевые бюджеты (обязательные)
- **Основная сборка ≤ 4.5 MB** итогового HTML (запас 10% до лимита 5 MB). Учитываем, что base64 раздувает ассеты на ~33%.
- **Lite-сборка ≤ 2.8 MB** (TikTok 3 MB, Moloco или Meta в формате ZIP). Делается на этапе 8 за счёт урезанных текстур и звука, геймплей не меняется.
- Работа **без единого сетевого запроса**, старт по MRAID `ready` и `viewable`, пауза и mute при потере видимости.
- Звук выключен до первого тапа.
- Минимальная платформа: **Android 7+, WebView Chrome 80+, WebGL 1.0** (WebGL 2 — когда доступен). Целевой слабый девайс: ~3 GB RAM, Mali-G52 / Adreno 610 класса (условно Redmi 9 / Samsung A12).
- Ориентация: **портрет — основная** (референс 720×1280). Ландшафт обязан корректно работать: камера показывает больше по горизонтали, UI перестраивается.
- Интерактивные элементы держать вне верхних и нижних ~10% экрана (там UI сетей) и вне углов 50×50 px.

### 2.3 Технологический стек (обязательный)
- **Unity 6000.0 LTS + URP 17.0.x** — именно эта связка в списке поддерживаемых Luna (Playworks Plugin). Более новые Unity 6.x не использовать, пока Luna их официально не поддерживает. Проверить на этапе 0.
- **Экспорт через Luna (Unity Playworks Plugin)**. Чистый Unity Web build в 5 MB single-HTML практически не влезает, а Luna — индустриальный стандарт для Unity-плееблов: сама собирает версии под каждую сеть.
- Ограничения Luna, которые определяют архитектуру:
  - **Нет DOTS/ECS, Burst, Jobs, DLL и нативных плагинов.** C# транспилируется в JS. Ориентир — C# 7.3, более новые фичи только после проверки Compiler V2.
  - Нет HDRP, Post Processing, 2D Lights, VFX Graph, GPU instancing. Шейдеры — Shader Target 3.0, совместимые с WebGL 1.
  - 2D-физика исторически работала нестабильно. **Физический движок мы не используем вообще**: вся коллизия считается по собственным маскам.
  - Не использовать Zenject, UniTask, async/await, LINQ в рантайме, рефлексию, IMGUI, UI Toolkit.

## 3. Геймплей

### 3.1 Общий цикл
```
Boot → Intro (камера на замке игрока, подсказка-рука)
 → PlayerAim → PlayerFire → Flight/Resolve (камера сопровождает)
 → [проверка победы]
 → AIAim → AIFire → Flight/Resolve
 → [проверка победы] → PlayerAim … 
 → Victory (камера: проигравший → победитель, пушки прыгают, фейерверк)
 → EndCard (PLAY NOW → стор)
```
- Первым ходит игрок (синий, слева). ИИ — красный, справа. Стороны задаются в конфиге.
- **Лимит длительности**: не более `maxPlayerTurns` (по умолчанию 3) ходов игрока или `maxSessionSeconds` (по умолчанию 60 с). По достижении — EndCard в любом случае.
- **Поражение игрока** тоже ведёт к EndCard (с текстом вроде «Try again in the full game!»). CTA одинаковый.
- **Режиссура (Director)**: по умолчанию сессия скриптована так, чтобы игрок выигрывал к 2–3-му ходу. ИИ наносит урон, но не добивает игрока до последнего разрешённого хода. Отключается флагом в конфиге.

### 3.2 Управление
- **Прицеливание**: зажать палец в любом месте экрана и вести. Угол = направление от замка игрока к точке касания (альтернатива в конфиге — «оттягивание», как у рогатки).
- Все пушки стороны **синхронно поворачиваются** в направлении прицела (плавно, `aimTurnSpeed`).
- Пунктир показывает первые ~25% траектории, без полной подсказки: упругий ограниченный угол, пунктир из точек.
- **Отпускание пальца = выстрел.** Угол ограничен `[aimMinDeg, aimMaxDeg]`.
- **Обучение**: в Intro анимированная рука показывает жест к бустеру x20. Через 3 с без ввода рука появляется снова. Через 10 с простоя (требование TikTok) происходит автовыстрел по «хорошему» углу. Автовыстрел **никогда не ведёт в стор**.

### 3.3 Пушки и залп
- Вид — «трёхстволка» в цвет стороны (синий / красный). Пушки торчат из стен замка в точках крепления (`CannonMount`) и в покое смотрят в сторону противника.
- При выстреле **все живые пушки стороны стреляют одновременно**, каждая выпускает **`rocketsPerCannon` = 10 ракет** последовательно с интервалом `rocketInterval` ≈ 0.06 с (стволы чередуются).
- Отдача — короткий откат ствола и вспышка у дула.
- **Попадание по пушке**: пушка уничтожается, если
  1. взрыв перекрыл её хит-круг (`cannonHitRadius`), **или**
  2. в маске замка исчез материал под точкой крепления, **или**
  3. кусок замка, на котором она висит, откололся.

  Уничтоженная пушка «отваливается»: получает импульс от взрыва и вращение, падает без коллизий за край уровня в воду (всплеск) и деспавнится.
- Количество пушек: **по умолчанию синий 3, красный 12** (в референсе синий 1, красный 14 — см. «Открытые вопросы»). Задаётся точками крепления в префабе замка.

### 3.4 Ракеты
- Траектория — **баллистика + синусоида**: базовая точка движется по параболе (`launchSpeed`, `gravity`), к ней добавляется смещение перпендикулярно скорости `A·sin(ωt + φ)`. Фаза φ у соседних ракет сдвинута, поэтому поток выглядит «змейкой» (кадры 1, 2, 9).
- Ракета ориентирована по касательной к фактической траектории.
- За каждой ракетой тянется дымный шлейф (оранжевый у сопла → серый дым). При большом числе ракет шлейф делается упрощённо (см. 5.4).
- Ракета **взрывается при первом касании материала** (земля, чужой замок, платформа). Свой замок ракеты игнорируют. Вылет за границы уровня или в воду — деспавн, в воде всплеск.
- Взрыв — вспышка, ударное кольцо, осколки, кратер в маске (см. 3.6) и урон пушкам в радиусе.
- Поток ракет, бьющих в одну точку, последовательно **прогрызает тоннель** (кадр 11 — до воды). Это должно получаться само собой, без спецлогики.

### 3.5 Бустеры
- Визуал: вертикальный прямоугольник, «стеклянный цилиндр в профиль». Полупрозрачный цветной корпус с бликами, непрозрачные заглушки сверху и снизу, крупная белая надпись с обводкой. Цвета: **x10 — синий, x20 — жёлтый/оранжевый, x50 — зелёный**.
- Размер ≈ 1×2 м (кадр 3).
- **Механика**: ракета, впервые пересёкшая бустер, заменяется на N ракет:
  - копии появляются на выходной стороне бустера с небольшим веером угла (`spreadDeg`) и разносом по времени (`spawnStagger`), так что выходят несколькими «змейками» (кадр 9);
  - у копии есть битовая маска «уже умножена бустером k», и тот же бустер её повторно не умножает. Другой бустер умножает.
- Бустер — триггер: не разрушается и не блокирует ракеты.
- **Жёсткий бюджет ракет** `maxActiveRockets` (по умолчанию 600, тестовый стресс — 1000). Когда спавн упирается в лимит, лишние копии не создаются. Вместо них оставшиеся получают `damageWeight` (больший радиус кратера), чтобы разрушение ощущалось соразмерно. UI-поп-ап над бустером всегда показывает «честное» число (`+200`).
- Каждое срабатывание бустера сопровождается «пыхом» и коротким сквошем корпуса.

### 3.6 Разрушаемость
**Все разрушаемые объекты** (ландшафт, замки) — это картинка плюс CPU-маска материала той же формы в пониженном разрешении (≈ 16 тексел/м, настраивается).

| Материал | Форма кратера | Вид края |
|---|---|---|
| Земля | Ровный круг радиуса `craterRadiusGround` | Тёмная кайма по краю выреза: земля «опалена» на `rimWidth` |
| Замок (камень) | «Погрызанный» круг: радиус с шумом, 8–12 зубцов | Затемнение по краю + **трещины**: тёмные ломаные линии наружу от кратера (кадры 6, 7, 11, 12) |
| Платформа (дерево) | Не вырезается | Только декаль трещин (кадр 12) |

- **Обрушение (сложнее, чем в Worms)**: после взрывов (батчем, не чаще раза в `connectivityInterval` ≈ 0.1 с) запускается проверка связности на грубой сетке:
  - у замка «опора» — нижний ряд, касающийся платформы;
  - у ландшафта «опора» — нижний край уровня (дно под водой).

  Всё, что потеряло связь с опорой, вырезается из маски и превращается в **падающий обломок**: спрайт-копия этого участка с гравитацией и лёгким вращением, **без коллизий**. Он улетает за край уровня, в воду (всплеск). Пушки на отколовшемся куске падают вместе с ним.
- Мелочь (островок меньше `minChunkCells`) не превращается в обломок, а просто исчезает с облачком пыли.
- Деревья и камни на ландшафте — декор, привязанный к точке поверхности. Если материал под ним исчез, декор падает (кадр 11, летящие ёлки).

### 3.7 Замки
- Два замка **разной формы**:
  - **синий** — компактный, две башни с синими коническими крышами, проём между ними (кадры 1, 10);
  - **красный** — высокий «собор» из 7 башен с красными крышами (кадр 4).

  Крыши в цвет стороны. Стены — светлый камень с кирпичной прорисовкой, окна-арки.
- Под замком **деревянная платформа** (с арочными воротами), под ней **две гусеницы** (слева и справа) с шестернями и шипами.
- **Наклон**: каждая гусеница поворачивается по нормали ландшафта под собой (высота ландшафта берётся из маски в её крайних точках). Угол платформы = `atan2(hR − hL, xR − xL)`. Замок жёстко сидит на платформе и наклоняется вместе с ней.
- Если под гусеницей выбило землю, замок плавно «оседает» к новой высоте. Если под обеими гусеницами пусто до воды — замок падает в воду, все его пушки считаются потерянными.
- **Покачивание от урона**: на каждый взрыв по замку — угловой импульс в сторону от точки взрыва, затухающая пружина, макс. ±3°. Импульсы от залпа суммируются, но насыщаются.

### 3.8 Уровень 1
Схема (слева направо), высоты относительно уровня воды; ориентиры сняты с кадров 2–4:
```
 [синий замок]      ___  [x20]  ___         [красный замок]
  на холмике      /    \  |  |  /    \        на холмике
 ___/‾‾‾\___     /      | |x10| |      \     ___/‾‾‾\___
            \___/       | |  | |        \___/           \__
                         |x50| |
 ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ вода
```
- Ширина уровня ≈ 60 м, высота горы ≈ 11–12 м над водой. Пологие холмы под замками ≈ 1.5–2 м над водой.
- Гора **разрезана вертикальной расщелиной** ≈ 1.4 м шириной до самой воды. Внутренние стенки почти вертикальные, внешние склоны крутые и вогнутые.
- Бустеры: **x20** — над расщелиной, чуть выше вершин. **x10** — в расщелине на верхней трети. **x50** — в расщелине у самого низа, над водой.
- **Задуманный «скилл-шот»**: прострелить половину горы насквозь, попасть ракетами в x10 или x50 в расщелине и пробить вторую половину. Простой путь — навесом через x20.
- Вода — анимированная полоса по низу уровня (волна по верхней кромке, блики, всплески).
- Над уровнем лёгкий дождь (тонкие штрихи), как в ролике. Включается флагом.
- Форма ландшафта задаётся **картинкой-маской** (`Level1_TerrainMask.png`, белое — земля). Картинку генерирует скрипт из SVG-источника, поэтому её легко править.

### 3.9 Камера (Director)
Одна ортографическая камера, все переходы плавные (SmoothDamp по позиции и `orthographicSize`, без рывков).

| Состояние | Кадр |
|---|---|
| Intro / PlayerAim | Замок игрока крупно, чуть смещён влево; виден сектор неба над ним |
| Залп игрока | Пауза ~0.3 с на замке → переезд к центру уровня (гора и бустеры) с **увеличением** масштаба. Камера следит за «центром масс» головы потока |
| Ракеты прошли центр | Переезд на вражеский замок; масштаб чуть меньше, чем в центре |
| Обстрел закончился | Задержка ~0.7 с на разрушениях, кадр остаётся на враге: он целится (пушки поворачиваются) и стреляет |
| Залп ИИ | Зеркально: враг → центр → замок игрока |
| Victory | Кадр на уничтоженном замке ~1 с → переезд на победителя |

- Небольшой **screen shake** от массовых взрывов, с насыщением.
- В ландшафте поле зрения шире, а точки интереса те же.
- Под отладочным флагом есть свободная камера (pinch / drag).

### 3.10 Фон (параллакс)
Слои, от дальнего к ближнему; коэффициент — доля смещения относительно камеры:
1. небо, вертикальный градиент (без текстуры, вершинные цвета) — 0.0;
2. облака, медленный дрейф — 0.05;
3. дальние горы, голубоватые, туманные — 0.15;
4. дальний лес (тёмно-зелёный силуэт, ели) — 0.3;
5. ближний лес и туман — 0.5.

Параллакс учитывает и смещение, и зум: дальние слои масштабируются слабее. Слои бесшовно тайлятся по X.

### 3.11 Победа и EndCard
- Победа — у противника **0 живых пушек**. Новые залпы прекращаются, летящие ракеты долетают, затем (≤ 1.5 с) начинается Victory.
- Victory: пушки победителя **радостно подпрыгивают** (синус-подскок со сдвигом фаз и сквошем), за замком — **фейерверк** (3–5 залпов разноцветных искр).
- Через ~2 с затемнение и EndCard: логотип **«CASTLE DESTROYERS»**, пульсирующая кнопка **«PLAY NOW»**. Нажатие — переход в Google Play через Luna API (`InstallFullGame`), который подставит нужный CTA под сеть. Тап по любому месту EndCard тоже ведёт в стор, это разрешено на финальном экране после геймплея.
- Арт EndCard — **оригинальный**. Персонажи, логотип и стиль конкретной чужой игры из ролика (там «Castle Busters») не копируем.

### 3.12 UI
- Поп-апы бустеров («+200»), рука-подсказка, EndCard, (опционально) маленькая постоянная кнопка «PLAY NOW» внизу безопасной зоны (`showPersistentCta`, по умолчанию off).
- Шрифт — один, жирный мультяшный, только нужные глифы (A–Z, 0–9, «x+!»). Либо надписи цифрами из спрайт-атласа.

### 3.13 Звук (минимум, следим за размером)
Выстрел (whoosh), взрыв (2 варианта), бустер (pop), всплеск, победа (short jingle), клик CTA. Все ≤ 1 с, кроме джингла. Mono, низкий битрейт. Общий бюджет ≤ 150 KB. Звук стартует только после первого тапа и глушится при потере видимости.

## 4. Графика
- Стиль — простая 2D мультяшная векторная графика: толстая тёмная обводка, плоская заливка с одной тенью, насыщенные цвета (кадры-референсы).
- **Источник арта** — SVG-файлы в `Art/Source/`, растеризуются скриптом в PNG нужного разрешения и пакуются в атлас. Первичный арт рисует Claude Code (SVG — код). Заказчик может заменить любой SVG своим, и пайплайн не меняется.
- Разрешение растеризации — под 720×1280 при самом крупном зуме камеры, не больше.
- Текстуры: игровой атлас ≤ 1024², замки — каждый ≤ 512×1024, фоновые слои — полосы 1024×256 (JPG там, где нет альфы). **Суммарно текстур ≤ 1.5 MB** до base64.

## 5. Техническая архитектура

### 5.1 Принципы
1. **Data-oriented managed C#** вместо DOTS (DOTS в Luna недоступен).
   - Горячие данные (ракеты, частицы, обломки) хранятся в **SoA — параллельных массивах примитивов** (`float[] posX, posY, velX…`), а не в массивах классов и не в `List<struct>`.
   - Bridge.NET эмулирует struct-ы объектами и **копирует их при присваивании**, то есть в JS это аллокация. Поэтому `Vector2`/`Vector3` в горячих циклах не используем, считаем на `float`.
2. **Ноль аллокаций в кадре**: все пулы выделяются при старте, максимальные размеры берутся из конфига. В рантайме нет `new`, LINQ, лямбд-замыканий, конкатенации строк, `foreach` по `List`, боксинга.
3. **Без физического движка**: коллизии — точечные и отрезочные тесты по маскам (O(1) на ракету), триггеры бустеров — проверка AABB.
4. **Один draw call на систему**: ракеты, дым, взрывы, искры, обломки рисуются через **динамические меши** (`Mesh.SetVertices/SetUVs/SetColors`, переиспользуемые буферы). SpriteRenderer — только для статичного и единичного (замки, пушки, бустеры, фон).
5. **Обновление масок по грязным тайлам**: маска ландшафта нарезана на тайлы 128×128. Каждый тайл — своя `Texture2D` и квад. За кадр перезаливаются только изменённые тайлы, и каждый не чаще одного раза.
6. **Детерминизм и настраиваемость**: все числа — в `GameConfig` (ScriptableObject) с осмысленными дефолтами, `[Range]` и тултипами. Seed рандома фиксируемый (`Random` свой, xorshift).
7. **Без DI-фреймворков**: один `GameBootstrap` (composition root) создаёт системы и передаёт зависимости через конструктор или `Init()`. Системы — обычные C#-классы с `Tick(dt)`. MonoBehaviour — только тонкие view и точки входа.

### 5.3 Маски
- Хранение: `byte[] solid` (0/1, 1 байт на тексел) + `byte[] shade` (кайма, трещины).
- Для GPU — `Texture2D` RGBA32 на тайл: R — материал (alpha-cutout), G — затемнение-кайма, B — трещины. Шейдер: `albedo = mainTex * (1 − G·k)`, поверх трещины, `clip(R − 0.5)`. Края сглаживаются билинейкой маски и smoothstep.
- Маска замка живёт в локальных координатах замка. При тесте ракеты точка переводится обратным преобразованием (замок наклонён и качается).
- Сетка связности — грубая (например, 1 ячейка = 4×4 тексела), пересчитывается только для затронутых объектов, батчем.
- **Фоллбэк** на случай, если Luna не поддерживает быструю запись в `Texture2D`: штамповка кратеров спрайтами в RenderTexture отдельной камерой. CPU-маска для коллизий остаётся та же. Выбор между вариантами делается на этапе 0.

### 5.4 Производительность и бюджеты

### 5.5 Интеграция с Luna
- Символ `UNITY_LUNA` — весь платформенный код за ним. В редакторе работают заглушки.
- CTA — `Luna.Unity.Playable.InstallFullGame()`. Конец геймплея — `Luna.Unity.LifeCycle.GameEnded()`. Пауза и резюм — через события жизненного цикла Luna. **Точные имена API сверить с актуальной документацией Luna на этапе 0.**
- Ссылки на стор (Google Play) задаются в настройках Luna (Playground), не хардкодом.
- Ключевые параметры баланса стоит пробросить как Playground-поля Luna (`[LunaPlaygroundField]`). Тогда креативщики смогут перебирать варианты без пересборки. Это опционально, на этапе 8.
