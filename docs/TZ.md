# Castle Destroyers — Техническое задание на плеебл (Unity → playable ad)

Версия: 1.1 · Дата: 2026-10-30
Источники:
- **механика** — текстовое описание заказчика, раскадровка `docs/references/*.jpg`, ролик `castle_destroyers_video.mp4`;
- **визуальный стиль** — игра Bowmasters, скриншоты в `docs/references/style/*.jpg`.

> **Изменения в 1.1**
> - Визуал переведён со стиля ролика на **стилистику Bowmasters** (§4, правки в §3.6–3.12).
> - Плеебл — **многокликовый**: 3 осмысленных хода игрока с нарастанием эффекта (§3.1, §3.2).
> - Прицел — по-боуместерски: «оттянуть» с силой и углом, плашка POWER / ANGLE, пунктир (§3.2).
> - Добавлен HUD в стиле Bowmasters: полосы «здоровья» сторон, индикатор хода (§3.12).
>
> Механика ролика (замки, пушки, залпы, бустеры, разрушаемость, камера) **не меняется**.

Термины: **плеебл** (playable ad) — интерактивная реклама в одном HTML-файле или ZIP-архиве. **Сторона**: синие (игрок) и красные (ИИ). **Залп** — одновременный выстрел всех живых пушек стороны. **Маска** — CPU-битмап «есть материал / нет материала» у разрушаемого объекта.

---

## 1. Цель продукта

Короткий (≈30–60 с) интерактивный рекламный ролик в стиле Worms. Игрок прицеливается, его замок даёт залп ракетами, ракеты размножаются в бустерах и сносят замок противника. В конце показывается экран с CTA «PLAY NOW», который ведёт в Google Play.

Ключевая эмоция — **«вау, сколько ракет»**: игрок выпускает несколько десятков ракет, а к цели прилетают сотни. Всё в кадре рушится, пробиваются тоннели насквозь.

**Формула**: механика ролика (дуэль замков, бустеры-умножители, разрушаемость) × **визуал и ощущение Bowmasters**: плоская векторная графика без обводок, монохромные локации, пошаговая дуэль с прицелом «сила + угол», HUD с полосами здоровья. Получается многокликовый плеебл, в котором игрок 3 раза сам прицеливается и стреляет, прежде чем получить CTA.

### 2.2 Наши целевые бюджеты (обязательные)
- **Основная сборка ≤ 4.5 MB** итогового HTML (запас 10% до лимита 5 MB). Учитываем, что base64 раздувает ассеты на ~33%.
- **Lite-сборка ≤ 2.8 MB** (TikTok 3 MB, Moloco или Meta в формате ZIP). Делается на этапе 8 за счёт урезанных текстур и звука, геймплей не меняется.
- Работа **без единого сетевого запроса**, старт по MRAID `ready` и `viewable`, пауза и mute при потере видимости.
- Звук выключен до первого тапа.
- Минимальная платформа: **Android 7+, WebView Chrome 80+, WebGL 1.0** (WebGL 2 — когда доступен). Целевой слабый девайс: ~3 GB RAM, Mali-G52 / Adreno 610 класса (условно Redmi 9 / Samsung A12).
- Ориентация: **портрет — основная** (референс 720×1280). Ландшафт обязан корректно работать: камера показывает больше по горизонтали, UI перестраивается. Bowmasters сам по себе горизонтальный, поэтому HUD в ландшафте раскладывается как в игре (полосы здоровья сверху по центру). В портрете HUD компактнее (§3.12).
- Интерактивные элементы держать вне верхних и нижних ~10% экрана (там UI сетей) и вне углов 50×50 px.

### 2.3 Технологический стек (обязательный)
- **Unity 6000.0 LTS + URP 17.0.x** — именно эта связка в списке поддерживаемых Luna (Playworks Plugin). Более новые Unity 6.x не использовать, пока Luna их официально не поддерживает. Проверить на этапе 0.
- **Экспорт через Luna (Unity Playworks Plugin)**. Чистый Unity Web build в 5 MB single-HTML практически не влезает, а Luna — индустриальный стандарт для Unity-плееблов: сама собирает версии под каждую сеть.
- Ограничения Luna, которые определяют архитектуру:
  - **Нет DOTS/ECS, Burst, Jobs, DLL и нативных плагинов.** C# транспилируется в JS. Ориентир — C# 7.3, более новые фичи только после проверки Compiler V2.
  - Нет HDRP, Post Processing, 2D Lights, VFX Graph, GPU instancing. Шейдеры — Shader Target 3.0, совместимые с WebGL 1.
  - 2D-физика исторически работала нестабильно. **Физический движок мы не используем вообще**: вся коллизия считается по собственным маскам.
  - Не использовать Zenject, UniTask, async/await, LINQ в рантайме, рефлексию, IMGUI, UI Toolkit.

## 3. Геймплей

### 3.1 Общий цикл
```
Boot → Intro (камера на замке игрока, подсказка-рука)
 → PlayerAim → PlayerFire → Flight/Resolve (камера сопровождает)
 → [проверка победы]
 → AIAim → AIFire → Flight/Resolve
 → [проверка победы] → PlayerAim … 
 → Victory (камера: проигравший → победитель, пушки прыгают, фейерверк)
 → EndCard (PLAY NOW → стор)
```
- Первым ходит игрок (синий, слева). ИИ — красный, справа. Стороны задаются в конфиге.
- **Лимит длительности**: не более `maxPlayerTurns` (по умолчанию 3) ходов игрока или `maxSessionSeconds` (по умолчанию 75 с). По достижении — EndCard в любом случае.
- **Поражение игрока** тоже ведёт к EndCard (с текстом вроде «Try again in the full game!»). CTA одинаковый.
- **Режиссура (Director)**: по умолчанию сессия скриптована так, чтобы игрок выигрывал к 2–3-му ходу. ИИ наносит урон, но не добивает игрока до последнего разрешённого хода. Отключается флагом в конфиге.

### 3.1.1 Многокликовая структура
Многокликовый плеебл — это несколько осмысленных действий игрока, в отличие от варианта «один тап → автопроигрывание → CTA». У нас **3 хода игрока**, каждый из них — отдельный жест «прицелиться и отпустить». Ходы растут по эффекту, и каждый учит новому:

| Ход | Подсказка (рука + подсветка) | Что игрок узнаёт | Ожидаемый результат |
|---|---|---|---|
| 1 | Рука тянет прицел так, чтобы пунктир смотрел на **x20** над горой | Прицел и залп | Залп × 20 → сотни ракет, первые пушки врага отваливаются |
| 2 | Подсветка (пульс) бустера **x50** в расщелине + рука на «прямой» угол в склон горы | Гору можно прострелить | Тоннель через левую половину → x50 → лавина ракет; враг теряет большую часть пушек |
| 3 | Без руки (если игрок не бездействует) | Свобода выбора | Добивание → Victory |

- Между ходами игрока — ход ИИ (ответный залп, драма, урон по замку игрока).
- Подсказки — данные в конфиге (`TurnHint[]`: целевой бустер, угол и сила руки, текст-плашка). Количество ходов и подсказки меняются без кода.
- Если игрок выиграл раньше 3-го хода — сразу Victory. Если на 3-м ходу не добил — Director даёт последнему залпу гарантированный «добивающий» множитель (докручивание `damageWeight`), игрок всё равно побеждает. При выключенном Director начинается ход ИИ и, возможно, поражение.
- Между ходами — короткая плашка хода «YOUR TURN!» / «ENEMY TURN» в стиле HUD (§3.12).
- CTA в стор срабатывает **только** с EndCard (или с опциональной мини-кнопки, §3.12) и никогда — от игровых тапов.
- Опционально (выключено, `bonusPickEnabled`): после 1-го хода показывается выбор из 2 карточек-бонусов («+1 пушка» / «+5 ракет в залпе»). Это ещё один клик-решение, характерный для многокликовых плееблов. Включается только по решению заказчика (§8).

### 3.2 Управление
Прицел устроен как в Bowmasters: тянешь — растут сила и угол, отпускаешь — выстрел.
- **Жест**: зажать палец в любом месте экрана и **тянуть назад**, от противника. Вектор «точка касания → текущая точка», развёрнутый на 180°, задаёт направление выстрела, его длина — силу.
  - Угол ограничен `[aimMinDeg, aimMaxDeg]`.
  - Сила = `clamp01(dragLength / aimMaxDragScreenFraction)` и отображается на `launchSpeed ∈ [launchSpeedMin, launchSpeedMax]`.
  - Мёртвая зона `aimDeadZone` — короткий тап не стреляет.
- Все пушки стороны **синхронно поворачиваются** в направлении прицела (плавно, `aimTurnSpeed`).
- **Плашка POWER / ANGLE** рядом с замком игрока: белая скруглённая «облачная» плашка с двумя крупными числами (`94%` и `24°`) и подписями `POWER` и `ANGLE` мелким капсом. Цвет текста — тёмно-фиолетовый из палитры HUD. Плашка появляется при начале жеста и исчезает после выстрела.
- **Пунктир траектории** — белые круглые точки, убывающие по размеру и прозрачности. Он показывает первые ~30% траектории (`aimPreviewFraction`): видно, куда целишься, но полная траектория не раскрывается. Синусоидальная «змейка» в превью не показывается, только базовая баллистика.
- **Отпускание пальца = выстрел.** Повторный жест во время полёта игнорируется.
- **Обучение**:
  - в начале каждого хода с подсказкой (§3.1.1) анимированная рука показывает жест «оттянуть», плашка POWER / ANGLE «играет» значениями;
  - через 3 с без ввода рука появляется снова;
  - через 10 с простоя (требование TikTok) — автовыстрел по углу и силе из подсказки текущего хода. Автовыстрел засчитывается как ход и **никогда не ведёт в стор**.

### 3.3 Пушки и залп
- Вид — «трёхстволка» в цвет стороны (синий / красный). Пушки торчат из стен замка в точках крепления (`CannonMount`) и в покое смотрят в сторону противника.
- При выстреле **все живые пушки стороны стреляют одновременно**, каждая выпускает **`rocketsPerCannon` = 10 ракет** последовательно с интервалом `rocketInterval` ≈ 0.06 с (стволы чередуются).
- Отдача — короткий откат ствола и вспышка у дула.
- **Попадание по пушке**: пушка уничтожается, если
  1. взрыв перекрыл её хит-круг (`cannonHitRadius`), **или**
  2. в маске замка исчез материал под точкой крепления, **или**
  3. кусок замка, на котором она висит, откололся.

  Уничтоженная пушка «отваливается»: получает импульс от взрыва и вращение, падает без коллизий за край уровня в воду (всплеск) и деспавнится.
- Количество пушек: **по умолчанию синий 3, красный 12** (в референсе синий 1, красный 14 — см. «Открытые вопросы»). Задаётся точками крепления в префабе замка.

### 3.4 Ракеты
- Траектория — **баллистика + синусоида**: базовая точка движется по параболе (`launchSpeed` — от силы прицела, §3.2; `gravity`), к ней добавляется смещение перпендикулярно скорости `A·sin(ωt + φ)`. Фаза φ у соседних ракет сдвинута, поэтому поток выглядит «змейкой» (кадры 1, 2, 9).
- Ракета ориентирована по касательной к фактической траектории.
- За каждой ракетой тянется шлейф в стиле Bowmasters: **плоские круглые «пуфы»** без градиентов. У сопла — жёлтый/оранжевый, дальше — пуфы цвета дыма из палитры локации, они растут и тают по альфе. При большом числе ракет шлейф делается упрощённо (см. 5.4).
- Ракета — плоская, без обводки: светлый корпус, головная часть и стабилизаторы в цвет стороны, одна тень-полоса вдоль корпуса.
- Ракета **взрывается при первом касании материала** (земля, чужой замок, платформа). Свой замок ракеты игнорируют. Вылет за границы уровня или в воду — деспавн, в воде всплеск.
- Взрыв — вспышка, ударное кольцо, осколки, кратер в маске (см. 3.6) и урон пушкам в радиусе.
- Поток ракет, бьющих в одну точку, последовательно **прогрызает тоннель** (кадр 11 — до воды). Это должно получаться само собой, без спецлогики.

### 3.5 Бустеры
- Визуал: вертикальный прямоугольник, «стеклянный цилиндр в профиль», но в плоском стиле Bowmasters:
  - полупрозрачная заливка цвета бустера;
  - 1–2 белые вертикальные полосы-блика;
  - непрозрачные скруглённые заглушки сверху и снизу на тон темнее;
  - крупная белая надпись `x20` округлым жирным шрифтом HUD. Вместо обводки — плоская тень на тон темнее, сдвинутая вниз.

  Цвета: **x10 — синий, x20 — жёлтый/оранжевый, x50 — зелёный**. Оттенки подобраны так, чтобы читались на тёмном фоне локации. Лёгкое «дыхание» (пульс масштаба ±3%).
- Размер ≈ 1×2 м (кадр 3).
- **Механика**: ракета, впервые пересёкшая бустер, заменяется на N ракет:
  - копии появляются на выходной стороне бустера с небольшим веером угла (`spreadDeg`) и разносом по времени (`spawnStagger`), так что выходят несколькими «змейками» (кадр 9);
  - у копии есть битовая маска «уже умножена бустером k», и тот же бустер её повторно не умножает. Другой бустер умножает.
- Бустер — триггер: не разрушается и не блокирует ракеты.
- **Жёсткий бюджет ракет** `maxActiveRockets` (по умолчанию 600, тестовый стресс — 1000). Когда спавн упирается в лимит, лишние копии не создаются. Вместо них оставшиеся получают `damageWeight` (больший радиус кратера), чтобы разрушение ощущалось соразмерно. UI-поп-ап над бустером всегда показывает «честное» число (`+200`).
- Каждое срабатывание бустера сопровождается «пыхом» и коротким сквошем корпуса.

### 3.6 Разрушаемость
**Все разрушаемые объекты** (ландшафт, замки) — это картинка плюс CPU-маска материала той же формы в пониженном разрешении (≈ 16 тексел/м, настраивается).

| Материал | Форма кратера | Вид края |
|---|---|---|
| Земля | Ровный круг радиуса `craterRadiusGround` | **Плоская** кайма ширины `rimWidth` цветом на тон темнее земли, без градиента. Жёсткая граница, как у слоёв ландшафта Bowmasters. Опционально кромка-«фестон» (мелкие полукруги, `rimScallop`) — повтор фирменной зубчатой кромки земли |
| Замок (камень) | «Погрызанный» круг: радиус с шумом, 8–12 зубцов | Плоская кайма на тон темнее камня + **трещины**: тёмные **плоские** ломаные клинья наружу от кратера, цвет — самый тёмный тон камня (кадры 6, 7, 11, 12 — по форме, не по цвету) |
| Платформа (дерево) | Не вырезается | Только декаль трещин (кадр 12) |

Принцип для всех разрушений: **никаких мягких градиентов и размытых теней**. Только 2–3 плоских тона одного цвета, как в Bowmasters. В шейдере маски кайма и трещины дают ступенчатое затемнение (`step`, а не плавный `smoothstep`). Сглаживается лишь 1 px самой кромки — против лесенки.

- **Обрушение (сложнее, чем в Worms)**: после взрывов (батчем, не чаще раза в `connectivityInterval` ≈ 0.1 с) запускается проверка связности на грубой сетке:
  - у замка «опора» — нижний ряд, касающийся платформы;
  - у ландшафта «опора» — нижний край уровня (дно под водой).

  Всё, что потеряло связь с опорой, вырезается из маски и превращается в **падающий обломок**: спрайт-копия этого участка с гравитацией и лёгким вращением, **без коллизий**. Он улетает за край уровня, в воду (всплеск). Пушки на отколовшемся куске падают вместе с ним.
- Мелочь (островок меньше `minChunkCells`) не превращается в обломок, а просто исчезает с облачком пыли.
- Деревья и камни на ландшафте — декор, привязанный к точке поверхности. Если материал под ним исчез, декор падает (кадр 11, летящие ёлки).

### 3.7 Замки
- Два замка **разной формы**:
  - **синий** — компактный, две башни с синими коническими крышами, проём между ними (кадры 1, 10);
  - **красный** — высокий «собор» из 7 башен с красными крышами (кадр 4).

  Крыши в цвет стороны. Стены — светлый камень с кирпичной прорисовкой, окна-арки. **Рисовка — Bowmasters**:
  - без обводок; формы простые, слегка скруглённые;
  - стена — 2 тона: основной + теневая сторона (вертикальная полоса на тон темнее);
  - кирпичи — редкие скруглённые прямоугольники на тон темнее;
  - крыша-конус — две половины: светлая и теневая;
  - окна — тёмные арки, у части окон тёплый «горящий» свет, как окна домов в Bowmasters;
  - флажок на шпиле в цвет стороны.

  Силуэты замков остаются как в ролике (форма читается за полсекунды).
- Под замком **деревянная платформа** (с арочными воротами), под ней **две гусеницы** (слева и справа) с шестернями и шипами. Всё в том же плоском стиле: гусеница — тёмная скруглённая лента и светлые круги-шестерни.
- **Наклон**: каждая гусеница поворачивается по нормали ландшафта под собой (высота ландшафта берётся из маски в её крайних точках). Угол платформы = `atan2(hR − hL, xR − xL)`. Замок жёстко сидит на платформе и наклоняется вместе с ней.
- Если под гусеницей выбило землю, замок плавно «оседает» к новой высоте. Если под обеими гусеницами пусто до воды — замок падает в воду, все его пушки считаются потерянными.
- **Покачивание от урона**: на каждый взрыв по замку — угловой импульс в сторону от точки взрыва, затухающая пружина, макс. ±3°. Импульсы от залпа суммируются, но насыщаются.

### 3.8 Уровень 1
Схема (слева направо), высоты относительно уровня воды; ориентиры сняты с кадров 2–4:
```
 [синий замок]      ___  [x20]  ___         [красный замок]
  на холмике      /    \  |  |  /    \        на холмике
 ___/‾‾‾\___     /      | |x10| |      \     ___/‾‾‾\___
            \___/       | |  | |        \___/           \__
                         |x50| |
 ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ вода
```
- Ширина уровня ≈ 60 м, высота горы ≈ 11–12 м над водой. Пологие холмы под замками ≈ 1.5–2 м над водой.
- Гора **разрезана вертикальной расщелиной** ≈ 1.4 м шириной до самой воды. Внутренние стенки почти вертикальные, внешние склоны крутые и вогнутые.
- Бустеры: **x20** — над расщелиной, чуть выше вершин. **x10** — в расщелине на верхней трети. **x50** — в расщелине у самого низа, над водой.
- **Задуманный «скилл-шот»**: прострелить половину горы насквозь, попасть ракетами в x10 или x50 в расщелине и пробить вторую половину. Простой путь — навесом через x20.
- **Земля в стиле Bowmasters**:
  - одна плоская масса цвета земли локации;
  - верхняя кромка — фирменная **волнистая / «капающая» полоса** другого, более светлого и насыщенного цвета (как зелёная «слизь» или красный «фестон» на скриншотах) толщиной ≈ 0.4 м. Под ней сразу основной цвет без перехода;
  - внутри массы — редкие плоские «закопанные» декоры на тон темнее (кости, камни, бутылки — свои, оригинальные), чтобы большая масса не была пустой.

  Кромка повторяет верх маски ландшафта: после разрушения в новых местах кромка не рисуется, там открыт «срез» почвы с плоской каймой (§3.6).
- Вода — плоская полоса из 2–3 тонов (основной, полоса бликов, светлая волнистая кромка), волна по верхней кромке, плоские всплески-капли.
- Дождь из ролика **выключен** по умолчанию: в Bowmasters его нет. Флаг `rainEnabled` оставляем.
- Декор поверхности (ёлки, кусты, камни, надгробия/фонари в зависимости от темы) — плоские силуэты 2 тонов без обводок.
- Форма ландшафта задаётся **картинкой-маской** (`Level1_TerrainMask.png`, белое — земля). Картинку генерирует скрипт из SVG-источника, поэтому её легко править.

### 3.9 Камера (Director)
Одна ортографическая камера, все переходы плавные (SmoothDamp по позиции и `orthographicSize`, без рывков).

| Состояние | Кадр |
|---|---|
| Intro / PlayerAim | Замок игрока крупно, чуть смещён влево; виден сектор неба над ним |
| Залп игрока | Пауза ~0.3 с на замке → переезд к центру уровня (гора и бустеры) с **увеличением** масштаба. Камера следит за «центром масс» головы потока |
| Ракеты прошли центр | Переезд на вражеский замок; масштаб чуть меньше, чем в центре |
| Обстрел закончился | Задержка ~0.7 с на разрушениях, кадр остаётся на враге: он целится (пушки поворачиваются) и стреляет |
| Залп ИИ | Зеркально: враг → центр → замок игрока |
| Victory | Кадр на уничтоженном замке ~1 с → переезд на победителя |

- Небольшой **screen shake** от массовых взрывов, с насыщением.
- В ландшафте поле зрения шире, а точки интереса те же.
- Под отладочным флагом есть свободная камера (pinch / drag).

### 3.10 Фон (параллакс)
Фон строится по принципу Bowmasters: **монохромная локация**. Все слои — плоские силуэты оттенков одного цвета, ступенчато по светлоте: чем дальше слой, тем он светлее и менее контрастен. Объём и глубина создаются только ступенями тона, без размытия и тумана-градиента.

Слои, от дальнего к ближнему; коэффициент — доля смещения относительно камеры:
1. небо — плоский цвет или очень мягкий 2-тоновый вертикальный градиент (вершинные цвета), редкие точки-звёзды для ночной темы — 0.0;
2. небесный объект (большая луна или солнце — плоский круг с парой кратеров-кругов) и облака-«пилюли» — 0.05;
3. дальние горы — крупные треугольные силуэты со скруглёнными вершинами, светлый тон — 0.15;
4. средний план — силуэт леса (ели-треугольники) **или** городка (дома-прямоугольники с окнами, часть окон горит), средний тон — 0.3;
5. ближний план — кусты, голые деревья, ограды, тёмный тон — 0.5.

Параллакс учитывает и смещение, и зум: дальние слои масштабируются слабее. Слои бесшовно тайлятся по X.

Опционально (`lightBeamEnabled`) — декоративный полупрозрачный белый «луч прожектора» по диагонали, как на скриншоте Bowmasters с кладбищем. Если мешает читаемости, выключаем.

### 3.11 Победа и EndCard
- Победа — у противника **0 живых пушек**. Новые залпы прекращаются, летящие ракеты долетают, затем (≤ 1.5 с) начинается Victory.
- Victory: пушки победителя **радостно подпрыгивают** (синус-подскок со сдвигом фаз и сквошем), за замком — **фейерверк**: 3–5 залпов **плоских** искр-кругов и звёздочек из палитры HUD, без свечения. Над победителем — плашка «VICTORY!» в стиле HUD.
- Через ~2 с затемнение (плоский полупрозрачный фиолетовый оверлей) и EndCard в стиле Bowmasters:
  - логотип **«CASTLE DESTROYERS»**: округлый жирный шрифт, белые буквы с плоской тенью, лёгкий наклон;
  - силуэт победившего замка;
  - пульсирующая кнопка **«PLAY NOW»** — скруглённая «пилюля» насыщенного цвета (жёлтый/оранжевый на фиолетовом фоне) с плоской нижней «толщиной».

  Нажатие — переход в Google Play через Luna API (`InstallFullGame`), который подставит нужный CTA под сеть. Тап по любому месту EndCard тоже ведёт в стор, это разрешено на финальном экране после геймплея.
- Арт EndCard — **оригинальный**. Персонажей, логотип и UI-иконки Bowmasters и игры из ролика («Castle Busters») не копируем: повторяем стиль, а не ассеты (см. §4.3).

### 3.12 UI
UI повторяет язык интерфейса Bowmasters:
- панели — **тёмно-фиолетовые полупрозрачные «пилюли»** с большим радиусом скругления;
- текст — белый, округлый жирный шрифт;
- акценты — розово-красный (полосы здоровья), золотой (иконки).

**HUD (во время боя)**
- **Полосы здоровья сторон** сверху по центру: слева синяя сторона, справа красная, между ними иконка «скрещённые ракеты» (своя, в духе скрещённых стрел Bowmasters). По краям — круглые рамки-«портреты» с **иконкой замка стороны** (силуэт башни с флажком в цвет стороны), а не персонажа.
  - Здоровье = живые пушки / начальные пушки. Полоса **сегментирована по числу пушек**: отвалилась пушка — гаснет сегмент, с коротким белым «миганием» и тряской полосы.
- **Индикатор хода** под полосами: «YOUR TURN!» / «ENEMY TURN», плашка-пилюля, появляется на 1 с при смене хода.
- **Плашка POWER / ANGLE** у замка игрока во время прицеливания (§3.2).
- Пауза, валюты и прочие элементы полной игры **не нужны**.
- Весь HUD — внутри безопасной зоны: ниже верхних ~10% экрана (там UI рекламных сетей) и вне углов 50×50 px. В портрете полосы короче и стоят двумя строками, если не помещаются в одну.

**Прочее**
- Поп-апы бустеров («+200») — белые цифры с плоской тенью, выпрыгивают и улетают вверх.
- Рука-подсказка — плоская, белая перчатка-указатель с тенью, своя.
- EndCard (§3.11), (опционально) маленькая постоянная кнопка «PLAY NOW» внизу безопасной зоны (`showPersistentCta`, по умолчанию off).
- Шрифт — один округлый жирный sans с открытой лицензией (например Fredoka или Baloo 2, OFL), подмножество глифов (A–Z, 0–9, «x+!%°»). Фирменный шрифт Bowmasters не используем.

### 3.13 Звук (минимум, следим за размером)
Выстрел (whoosh), взрыв (2 варианта), бустер (pop), всплеск, победа (short jingle), клик CTA. Все ≤ 1 с, кроме джингла. Mono, низкий битрейт. Общий бюджет ≤ 150 KB. Звук стартует только после первого тапа и глушится при потере видимости.

## 4. Графика — стилистика Bowmasters

Референсы стиля — `docs/references/style/bowmasters_*.jpg`. Кадры ролика задают только **что** и **где** (формы, композицию, поведение), но не **как нарисовано**.

### 4.1 Правила стиля
1. **Плоский вектор без обводок.** Никаких контуров, никаких мягких теней и бликов-градиентов. Каждая форма — 1 основной тон, плюс 1 теневой (сторона или нижняя часть), плюс при необходимости 1 бликовый.
2. **Простые геометричные формы** со скруглёнными углами: треугольники-ели, прямоугольники-дома, круги-кусты. Минимум мелких деталей, силуэт важнее фактуры.
3. **Монохромные локации**: весь фон — оттенки одного цвета, глубина передаётся ступенями светлоты (§3.10). Игровые объекты (замки, ракеты, бустеры, HUD) — контрастные и насыщенные, они «выпрыгивают» из фона.
4. **Земля** — плоская масса с фирменной волнистой или «капающей» цветной кромкой и редкими «закопанными» декорами (§3.8).
5. **Эффекты плоские**: взрыв — 2–3 концентрических круга-«звезды» (белый → жёлтый → оранжевый) плюс разлёт плоских кругов-осколков; дым — плоские пуфы; искры — круги и 4-лучевые звёзды. Без additive-свечения и размытия.
6. **Анимация «мягкая и упругая»**: сквош и стретч на выстреле, срабатывании бустера, отрыве пушки, подскоке победителя; ease-out-back на появлении UI.
7. **UI** — фиолетовые полупрозрачные пилюли, белый округлый шрифт, розово-красные полосы здоровья (§3.12).

### 4.2 Палитра (ScriptableObject `ThemePalette`, 2 пресета)
- **`Night` (по умолчанию)** — как кладбище и ночной город Bowmasters:
  - фон — тёмно-синий / индиго, ступени от `#1E1F5C` (ближний) до `#5C6FC2` (дальний);
  - звёзды, бледная луна;
  - земля — тёмно-зелёная масса с ярко-зелёной «слизистой» кромкой `#3FE07A`-класса;
  - вода — бирюзовая;
  - на тёмном фоне хорошо читаются светлый камень замков, красные и синие крыши (синие крыши чуть светлее и бирюзовее, чтобы не тонуть в индиго) и цветные бустеры.
- **`Sunset`** — как пустыня Bowmasters:
  - фон — коралловый, розовый, персиковый;
  - земля — красная масса с «фестонной» кромкой;
  - вода — синяя.

  У красного замка в этом пресете крыша смещается к бордовому для контраста.
- Цвета HUD общие для обоих пресетов: фиолетовая панель `≈ #4B2463` с альфой 0.85, полосы здоровья `≈ #F0335A`, золото `≈ #F5C443`.
- Точные HEX подбираются на этапе 7 по скриншотам-референсам (пипеткой) и фиксируются в пресетах.

### 4.3 Что повторяем и что нет
- **Повторяем**: стиль, приёмы, композицию интерфейса, характер анимации, тип палитры.
- **Не повторяем**: персонажей Bowmasters, их лица и костюмы, логотип и название, конкретные иконки (портреты, монеты, черепа-валюту), фирменный шрифт, конкретные фоны 1:1. В игре нет персонажей. Вместо портретов в HUD — иконки замков.
- Если заказчик (правообладатель) выдаст официальные ассеты Bowmasters, они подставляются через тот же пайплайн (замена SVG или PNG) без изменения кода.

### 4.4 Пайплайн
- **Источник арта** — SVG-файлы в `Art/Source/`, растеризуются скриптом в PNG нужного разрешения и пакуются в атлас. Первичный арт рисует Claude Code (SVG — код). Заказчик может заменить любой SVG своим, и пайплайн не меняется.
- Разрешение растеризации — под 720×1280 при самом крупном зуме камеры, не больше.
- Текстуры: игровой атлас ≤ 1024², замки — каждый ≤ 512×1024, фоновые слои — полосы 1024×256 (JPG там, где нет альфы). **Суммарно текстур ≤ 1.5 MB** до base64.

## 5. Техническая архитектура

### 5.1 Принципы
1. **Data-oriented managed C#** вместо DOTS (DOTS в Luna недоступен).
   - Горячие данные (ракеты, частицы, обломки) хранятся в **SoA — параллельных массивах примитивов** (`float[] posX, posY, velX…`), а не в массивах классов и не в `List<struct>`.
   - Bridge.NET эмулирует struct-ы объектами и **копирует их при присваивании**, то есть в JS это аллокация. Поэтому `Vector2`/`Vector3` в горячих циклах не используем, считаем на `float`.
2. **Ноль аллокаций в кадре**: все пулы выделяются при старте, максимальные размеры берутся из конфига. В рантайме нет `new`, LINQ, лямбд-замыканий, конкатенации строк, `foreach` по `List`, боксинга.
3. **Без физического движка**: коллизии — точечные и отрезочные тесты по маскам (O(1) на ракету), триггеры бустеров — проверка AABB.
4. **Один draw call на систему**: ракеты, дым, взрывы, искры, обломки рисуются через **динамические меши** (`Mesh.SetVertices/SetUVs/SetColors`, переиспользуемые буферы). SpriteRenderer — только для статичного и единичного (замки, пушки, бустеры, фон).
5. **Обновление масок по грязным тайлам**: маска ландшафта нарезана на тайлы 128×128. Каждый тайл — своя `Texture2D` и квад. За кадр перезаливаются только изменённые тайлы, и каждый не чаще одного раза.
6. **Детерминизм и настраиваемость**: все числа — в `GameConfig` (ScriptableObject) с осмысленными дефолтами, `[Range]` и тултипами. Seed рандома фиксируемый (`Random` свой, xorshift).
7. **Без DI-фреймворков**: один `GameBootstrap` (composition root) создаёт системы и передаёт зависимости через конструктор или `Init()`. Системы — обычные C#-классы с `Tick(dt)`. MonoBehaviour — только тонкие view и точки входа.

### 5.2 Модули (папки `Assets/_Game/Scripts/…`)
| Модуль | Ответственность |
|---|---|
| `Core` | Bootstrap, GameLoop (единый Update → Tick систем по порядку), GameConfig, Rng, пулы, события (простые C#-делегаты без аллокаций) |
| `Flow` | Стейт-машина сессии (3.1), многокликовая структура ходов и `TurnHint[]` (3.1.1), лимиты, Director-скрипт |
| `Input` | Тач и мышь → AimIntent (угол + сила, жест «оттянуть», мёртвая зона); idle-таймеры; блокировка ввода по состоянию |
| `Destruction` | `DestructibleMask` (CPU-маска + тайлы + upload), `CraterStamper` (круг, погрызанный круг, кайма, трещины), `ConnectivitySolver` (flood fill на грубой сетке), `ChunkExtractor` (вырез острова → обломок) |
| `Combat` | `RocketSystem` (SoA, траектории, коллизии, бюджет), `CannonSystem` (крепления, наведение, залп, отрыв), `BoosterSystem`, `ExplosionSystem` |
| `Castle` | Модель замка: маска + маунты + платформа и гусеницы, наклон, sway, проверка «жив ли» |
| `AI` | Выбор угла: набор «хороших» углов из пресета плюс шум по сложности; учёт Director |
| `Camera` | CameraDirector (точки интереса, SmoothDamp, shake), Parallax |
| `Fx` | Batched-рендереры плоских частиц: дым-пуфы, искры, всплески, фейерверк, пыль, (дождь — выкл.) |
| `UI` | HUD в стиле Bowmasters (сегментированные полосы здоровья, иконки замков, индикатор хода), плашка POWER / ANGLE, пунктир, рука-туториал, поп-апы, EndCard, CTA. `ThemePalette` применяется ко всем view |
| `Platform` | Обёртка над Luna API (`#if UNITY_LUNA`): CTA, GameEnded, viewability-пауза, звук. В редакторе — заглушки с логом |
| `DebugTools` | Оверлей (FPS, ракеты, аплоады тайлов, кучи), чит-кнопки (только dev-сборка, вырезается из релиза) |

### 5.3 Маски
- Хранение: `byte[] solid` (0/1, 1 байт на тексел) + `byte[] shade` (кайма, трещины).
- Для GPU — `Texture2D` RGBA32 на тайл: R — материал (alpha-cutout), G — затемнение-кайма, B — трещины. Шейдер: `albedo = mainTex * (1 − G·k)`, поверх трещины, `clip(R − 0.5)`. Края сглаживаются билинейкой маски и smoothstep.
- Маска замка живёт в локальных координатах замка. При тесте ракеты точка переводится обратным преобразованием (замок наклонён и качается).
- Сетка связности — грубая (например, 1 ячейка = 4×4 тексела), пересчитывается только для затронутых объектов, батчем.
- **Фоллбэк** на случай, если Luna не поддерживает быструю запись в `Texture2D`: штамповка кратеров спрайтами в RenderTexture отдельной камерой. CPU-маска для коллизий остаётся та же. Выбор между вариантами делается на этапе 0.

### 5.4 Производительность и бюджеты
| Метрика | Цель |
|---|---|
| FPS | 60 на среднем Android, **≥ 30 на слабом при 600 ракетах** и активных разрушениях |
| Draw calls | ≤ 40 в кадре |
| Аплоад масок | ≤ 4 тайла 128² на кадр (остальное — в очередь на следующие кадры) |

| JS heap | ≤ 150 MB пик, без роста за сессию |
| Загрузка | Первый кадр ≤ 3 с на слабом девайсе |

### 5.5 Интеграция с Luna
- Символ `UNITY_LUNA` — весь платформенный код за ним. В редакторе работают заглушки.
- CTA — `Luna.Unity.Playable.InstallFullGame()`. Конец геймплея — `Luna.Unity.LifeCycle.GameEnded()`. Пауза и резюм — через события жизненного цикла Luna. **Точные имена API сверить с актуальной документацией Luna на этапе 0.**
- Ссылки на стор (Google Play) задаются в настройках Luna (Playground), не хардкодом.
- Ключевые параметры баланса стоит пробросить как Playground-поля Luna (`[LunaPlaygroundField]`). Тогда креативщики смогут перебирать варианты без пересборки. Это опционально, на этапе 8.

## 8. Открытые вопросы (дефолты уже выбраны — меняются в конфиге)
1. Число пушек: синий 3 / красный 12 (в референсе 1 / 14). При 1 пушке игрок проигрывает с первого же ответного залпа.
2. Режиссура «игрок выигрывает к 3-му ходу» — включена.
3. Прицел — «оттянуть» с силой и углом, как в Bowmasters (вкл.). Альтернатива в конфиге — «направление на палец» без силы, проще для рекламы. Нужно решить по итогам плейтеста.
4. Постоянная мини-кнопка CTA во время игры — выключена.
5. Ссылка Google Play — плейсхолдер `com.example.castledestroyers`, задаётся в Luna.
6. Уровень 2 из ролика — не делаем.
7. Палитра по умолчанию — `Night` (тёмно-синяя, как кладбище Bowmasters); альтернатива — `Sunset`.
8. Бонус-выбор между ходами (`bonusPickEnabled`) — выключен. Включить, если нужно больше кликов-решений.
9. Число ходов игрока — 3 (`maxPlayerTurns`). Для более короткой версии — 2.
10. Персонажи-командиры на замках в духе Bowmasters — **не делаем**. Если нужны, их рисуют с нуля (оригинальные), это отдельный объём работ.
