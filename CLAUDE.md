# CLAUDE.md — Castle Destroyers (Unity playable ad)

Ты разрабатываешь рекламный плеебл (Worms-like дуэль замков) на Unity с экспортом через Luna (Unity Playworks).
Источники истины, по приоритету:
1. `docs/TZ.md` — что делаем;
2. `docs/ROADMAP.md` — в каком порядке;
3. `docs/DECISIONS.md` — принятые решения;
4. `docs/reports/` — что уже сделано.

Референс-кадры — `docs/references/*.jpg`. Открывай их при любых вопросах про вид и поведение.

## Режим работы (обязательно)
1. Работаешь **строго в рамках текущего этапа** из ROADMAP. Не забегай вперёд и не переписывай чужие этапы без причины.
2. Начало этапа: прочитай этот файл, раздел этапа в ROADMAP, нужные разделы TZ, DECISIONS и прошлые отчёты. Создай план задачами (TaskCreate). Создай ветку `stage/NN-short-name`.
3. Внутри этапа действуешь автономно: архитектурные мелочи, нейминг, дефолты параметров, мелкий визуал — решаешь сам.
4. **Стоп и вопрос** (не решай сам), если:
   - нужно менять стек или версию Unity, добавлять пакет или плагин;
   - требование ТЗ невыполнимо или его хочется изменить;
   - бюджет размера или FPS превышен и не решается в рамках этапа;
   - задача неоднозначна так, что неверное решение дорого переделывать.
5. Конец этапа:
   - код компилируется (batchmode), тесты зелёные;
   - Luna smoke-build собран (с этапа 3);
   - отчёт `docs/reports/STAGE_NN.md` по шаблону ниже;
   - коммит;
   - **остановка**. Следующий этап — только после сообщения `APPROVED`.
6. На `FEEDBACK:` правишь в той же ветке. В отчёт добавляешь раздел «Итерация K» со списком «пункт фидбека → что сделано → как проверить».
7. Любое отклонение от ТЗ → запись в `docs/DECISIONS.md` (контекст, решение, альтернативы, статус: принято / нужно подтверждение).

## Стек и жёсткие ограничения (Luna)
- Unity **6000.0 LTS**, URP 17.0.x (Universal Renderer). Других версий не ставить.
- C# **уровня 7.3**. Никаких records, switch-expressions, `init`, nullable reference types, default interface methods.
- **Запрещено** в рантайм-коде:
  - DOTS/ECS, Jobs, Burst, DLL и нативные плагины;
  - Zenject, UniTask, async/await, Task, рефлексия, LINQ, `dynamic`;
  - IMGUI (`OnGUI`), UI Toolkit;
  - Physics/Physics2D (коллизии считаются по своим маскам), Shader Graph, VFX Graph, Post Processing, 2D Lights, GPU instancing;
  - `goto`, деструкторы, inline-касты (`if (x is Foo f)` — сначала объяви переменную).
- UI — uGUI (+ TextMeshPro, если подтверждён в спайке). Шейдеры — HLSL, Shader Target 3.0, совместимы с WebGL 1.
- Платформенный код (CTA, жизненный цикл) — только в модуле `Platform` за `#if UNITY_LUNA`, в редакторе заглушки.
- Debug-код — за `#if GAME_DEBUG`, в релизной сборке его нет.

## Правила производительности (горячие пути: ракеты, частицы, маски)
- Данные — **SoA в массивах примитивов** (`float[]`, `int[]`, `byte[]`). Никаких массивов struct-ов и `Vector2/3` в горячих циклах: Luna (Bridge.NET) копирует struct-ы аллокацией.
- **Ноль аллокаций в кадре**: всё выделяется в `Init` по лимитам из `GameConfig`. Нет `new` в `Tick`, нет замыканий, боксинга, `string +`, `foreach` по `List`.
- Рендер массовых объектов — один динамический меш на систему с переиспользуемыми буферами. Никаких GameObject на ракету.
- Маски — заливка только грязных тайлов, лимит аплоадов на кадр. Связность — батчем по таймеру, на грубой сетке.
- Любой новый тип «массового» объекта — сразу с пулом, лимитом в конфиге и LOD-стратегией.

## Код
- Структура: `Assets/_Game/{Scripts/<Module>, Art, Shaders, Prefabs, Scenes, Configs}`. Модули — по TZ §5.2. Asmdef: `Game.Runtime`, `Game.Editor`, `Game.Tests`.
- Системы — обычные C#-классы с `Init(...)` и `Tick(float dt)`. Порядок Tick задаёт `GameLoop`. MonoBehaviour — тонкие view и entry point.
- Все настраиваемые числа — в `GameConfig` (ScriptableObject) с `[Range]`, `[Tooltip]` (по-русски), группировкой `[Header]`. Магических чисел в коде нет.
- Один `GameBootstrap` — composition root. Зависимости передаются явно.
- Тесты: EditMode — для чистой логики (маски, связность, траектории, FSM, бустеры, бюджет ракет).
- Комментарии и логи — на русском или английском, единообразно в пределах файла. Публичные классы — с коротким XML-summary.

## Команды (Windows)
```
# компиляция + EditMode-тесты
"C:\Program Files\Unity\Hub\Editor\6000.0.85f1\Editor\Unity.exe" -batchmode -nographics -projectPath . -runTests -testPlatform EditMode -testResults Logs/tests.xml -logFile Logs/editor.log
# растеризация арта
python Tools/rasterize_svg.py   (появится на этапе 7)
```
После batchmode всегда читай `Logs/editor.log` на предмет `error CS` и исключений.

## Арт
- Арт рисуешь как **SVG-код** в `Art/Source/`. Стиль: мультяшный вектор, толстая тёмная обводка, плоская заливка + одна тень, насыщенные цвета (см. references).
- Не копируй чужие персонажи, логотипы и арт из ролика. Всё оригинальное. Логотип — «CASTLE DESTROYERS».
- PNG генерируются скриптом и не правятся руками.
